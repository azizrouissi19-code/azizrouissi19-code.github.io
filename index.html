// how I build AI

AI that proposes. Systems that decide.

Across robots, financial workflows and documents, I use the same principle: never let a model act on the real world without a layer that checks it first.

01 · PROPOSE

The model suggests

LLM agents and vision models output a structured proposal through tool / function calling, never a raw command.

→
02 · VALIDATE

Guardrails check

Strict JSON schemas, whitelisted actions, least-privilege permissions, prompt-injection checks and an independent safety layer.

→
03 · EXECUTE

Safe, traced action

Only valid actions run, with audit logs and human approval for sensitive steps. Anything else falls back to a safe state.

CARTHANIT: Companion Robot for Children with Autism

LLM decision layer running locally on a Raspberry Pi

A robot that interacts with vulnerable children cannot trust an LLM blindly. I designed its decision layer so that the model only proposes an action from a fixed whitelist and never generates motor commands.

  • Every LLM output is validated against a strict schema, the child's profile and an independent safety layer.
  • Invalid proposals are discarded and the robot stays in a safe state.
  • Runs locally (Edge AI) on a Raspberry Pi with ROS 2 and an ESP32.
